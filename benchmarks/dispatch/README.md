# Dispatch baseline

This harness captures the pre-cleanup dispatch baseline requested by
REQUIREMENTS.md. It compares:

- a concrete Rust generic receiver;
- an Arc<dyn FsDriver> Rust receiver;
- the built N-API package as exercised from Node.

The generic lane is explicitly labelled **generic receiver still boxed by
async-trait**. A concrete type does not remove the boxed future generated by
the current trait ABI, and FsDriver::open still returns
Arc<dyn FileHandle>. This benchmark does not refactor either adapter.

## Smoke run

From the repository root:

    node benchmarks/dispatch/runner.mjs --smoke --output /tmp/mount-rs-dispatch-smoke.json

Smoke is the default profile, so the --smoke flag is optional. It runs small
stat/open-close/read/write operations over the memory and memory-backed
chunked drivers, with one worker and 32/4096-byte payloads. The runner invokes
the existing release example with cargo --locked and loads the existing N-API
artifact; it does not install dependencies or change Cargo manifests.

The N-API artifact must already be available at
bindings/mount-rs-napi/index.js. If it is not built, run the repository's
existing N-API build procedure first.

## Thorough and custom runs

The larger sweep includes 1/4/16 workers, 32/4096/65536-byte payloads, and
4096/65536-byte fixed chunks:

    node benchmarks/dispatch/runner.mjs --thorough --output /tmp/mount-rs-dispatch-thorough.json

Every setting is overrideable:

    node benchmarks/dispatch/runner.mjs --smoke \
      --iterations 2000 --samples 10 --warmup 500 \
      --concurrency 1,4,16 \
      --payload-sizes 32,4096,65536 \
      --chunk-sizes 4096,65536,1048576 \
      --operations stat,open_close,read,write \
      --output /tmp/mount-rs-dispatch-custom.json

Use --skip-rust or --skip-node for a one-sided diagnostic run. Those options
are useful when an already-built artifact or the Rust toolchain is not
available, but a complete comparison should include both surfaces.

The Rust child has a bounded outer timeout (120 seconds by default):

    node benchmarks/dispatch/runner.mjs --smoke --rust-timeout-ms 300000

N-API shutdown is also bounded (10 seconds by default) because the successful
measurement checkpoint is written while adapter instances are still alive.
Override it with --cleanup-timeout-ms when diagnosing a slow backend.

## Report contract

The report is raw JSON and includes provenance captured before measurements:

- source-control gitHead, dirty flag, and dirty-entry count;
- the loaded N-API binding target and the SHA-256 of the actual loaded .node
  artifact when native code is used;
- an explicit marker that source gitHead is not being presented as the binary
  revision.

The report never substitutes the repository HEAD for a native binary hash.
If required provenance cannot be captured, the run exits with an error report
and records no measurements.

Each lane retains one sample record per timed batch:
duration, operation count, nanoseconds per operation, and Rust global
allocator deltas. Operation and byte throughput are retained for each
applicable sample. Summary median/p95/p99 values are derived from those raw
values without rounding.

When --output is supplied, the real measurement report is first saved with
cleanup status pending, before N-API adapter shutdown. After successful
cleanup it is finalized with cleanup status complete. A timeout or execution
failure produces status error, measurements not-recorded, and a non-zero exit
instead of fabricating timing samples. With --output, stdout is intentionally
concise and prints only a JSON status/output-path/cleanup record; the full raw
report remains at the requested path. Without --output, the full report is
printed to stdout.

Rust allocation counts are process-global allocator deltas sampled around the
timed async operation. Fixture buffers and handles are prepared before the
timed region. Concurrency greater than one includes the worker scheduling
control path. Node/V8 allocation counts are deliberately null and labelled
unavailable-js-v8; the runner does not infer allocations from heap usage.

The Node lane uses the public FileHandle.read/write API. It does not borrow or
expose a N-API backing-buffer subslice across an await: JavaScript can access
or mutate that buffer while the Rust future is suspended, so such a change
would not be a safe baseline optimization.

The root example is auto-discovered by Cargo:

    cargo run --release --example dispatch_baseline -- \
      --warmup 100 --iterations 500 --samples 5 \
      --concurrency 1 --payload-sizes 32,4096 --chunk-sizes 4096 \
      --operations stat,open_close,read,write

This directory and examples/dispatch_baseline.rs are baseline-owned files.
No adapter cleanup, CI wiring, or Cargo manifest edit is part of the harness.
