## Explicit boundaries

- Local Rust and loopback structural-driver tests are not live AWS or
  Cloudflare R2 acceptance.
- A missing or expired provider credential is a blocked external prerequisite,
  not a passing service result.
- Native Linux/Windows/macOS mount and hosted lanes remain separate from this
  mount-free transport evidence.
- The Node `./s3` package entry intentionally supports the N-API
  server/session facade; the oracle-only pure codec/helper barrel is Rust-owned
  and is not counted as Node parity.

## Supported-scope decisions

These are deliberate product boundaries, not implied claims that every upstream
or deployment-specific S3 behavior is already accepted.

| Area | Decision | Evidence and remaining boundary |
| --- | --- | --- |
| Node public API | Support the N-API `S3Server`/`S3Session` facade, streaming body bindings, bucket/session views, connection hooks, and structural-driver factory identity. Keep the 153 pure oracle codec/helper exports Rust-owned rather than manufacturing a partial JavaScript mirror. | `MOUNTX_SOURCE=/private/tmp/mountx-source-w01-20260921 node test/s3-barrel-scope.mjs`, package typecheck/distribution, and host-enabled `node test/servers.mjs`; the exact export-scope count is evidence of the boundary, not complete upstream parity. |
| S3 protocol | Support path-style core object operations, ListObjectsV2 with `/` delimiter, ranges/conditionals, copy, DeleteObjects, and multipart create/upload/list/complete/abort. Deliberately refuse ListObjects V1, bucket create/delete, GET/HEAD `partNumber`, and non-`/` delimiters with the documented S3 `NotImplemented` boundary. | `transports/mount-rs-s3/README.md`, `oracle_refusal_boundaries_keep_their_protocol_reasons`, and the Rust HTTP differential cover the supported/refused protocol shapes. Unsupported operations remain explicit scope decisions, not production blockers for the declared subset. |
| Streaming | Support session-level buffered and async streaming request/response paths with bounded staging, cancellation cleanup, and atomic publication. Do not claim the bundled Axum listener is the upstream's fully incremental request-body server; it buffers each request up to the configured limit. | Rust gateway streaming tests, host-enabled `node test/servers.mjs`, and `node scripts/check-http-parity.mjs`; fully incremental upstream-server parity is outside the declared transport scope. |
| Durability | Support a conditional durability contract: a driver advertising `durable_writes` must pass `syncfs` before a successful mutation is acknowledged; volatile drivers do not receive a power-loss guarantee. | `durability_barrier` in the S3 session and `durable_mutations_wait_for_and_report_syncfs_barriers`; physical power-loss/torn-write evidence and provider-backed durability remain deployment gates and are not accepted by local tests. |
| Native mount boundary | Treat FUSE/NFS/macFUSE/Linux-kernel mounting as not applicable to this mount-free S3 HTTP transport. Native mount qualification for other transports and the hosted N-API lifecycle lane remain separate evidence streams. | The S3 README states the boundary; local loopback and host-enabled N-API checks must not be promoted to native mount or hosted-provider acceptance. |
| Live providers and hosted lanes | Keep AWS S3, Cloudflare R2, and native/hosted lifecycle acceptance as required external gates rather than scoping them out. | Current workflow admission evidence is recorded above; credentials, provider budget/configuration, and fresh service results remain externally supplied prerequisites, so production stays NO-GO. |
