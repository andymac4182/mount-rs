# Mount ownership and exclusive writeback

User approved explicit ownership modes, exclusive-first SQLite qualification, correctness tests and benchmarks on 2026-09-24.

The chunked engine already implements exclusive fenced volume leases and shared revision-CAS operation. Expose these as Exclusive and Shared ownership modes. Preserve legacy concurrent_writes configuration; reject contradictory simultaneous declarative ownership configuration in CLI/N-API. Fluent Rust builders retain their usual last-setter semantics, with invalid final shared/writeback combinations rejected at open. Explicit Exclusive enables deferred publication; legacy construction preserves existing write-through behavior for compatibility. Shared continues bound concurrent-CAS semantics and disallows writeback. Shared SQLite remains unsupported across independent mounts: no distributed POSIX locks or wal-index are implied.

Exclusive writes update the coordinator's local namespace and immutable blocks without publishing each change. Required barriers flush blocks, provider-check the lease, publish the complete staged namespace using the persisted revision, and establish the metadata durability barrier. File fsync, directory fsync, syncfs and orderly shutdown drain pending state. Failed or canceled publication fails closed. Expiry recovery must not discard pending state, and takeover must fence the old owner. Reconciliation must preserve both published and staged block roots, or drain first. Local operation generations must preserve optimistic conflict detection when the persisted revision does not advance per mutation.

Expose OwnershipMode and a separate explicit writeback switch in chunked options and SDK builders; CLI structured storage accepts ownership_mode exclusive/shared. Keep no-config defaults compatible. Do not bypass provider durability/fencing. Tests cover local visibility, reopen after sync/shutdown, atomic namespace operations, overlapping writes, stale ownership, sync failure/cancellation, GC, legacy configuration and shared compatibility. Benchmark identical random-write and namespace workloads using write-through versus exclusive writeback, memory and durable SQLite stores, provider operation counts and repeat latency distributions. Native Linux FUSE SQLite is a distinct required qualification; find an available Linux environment and record evidence without upgrading unsupported cross-client SQLite.
