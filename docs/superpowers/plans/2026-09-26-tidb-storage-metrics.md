# TiDB storage metrics implementation plan

Source basis: `1ad3a1a12e29a1743534bca42b0c3cec4049e0f9`, 2026-09-26. This slice changes only the TiDB provider, its focused new test, and this plan. Core recorder operation names and `Span::finish_success_with_rows(bytes, rows)` are reserved by the separate core owner. No workload, SQL semantics, pool limit, fixture, or dependency changes are authorized here. The source lease was later expanded narrowly to the existing `inode_batch.rs` helper and a public coverage reexport in `lib.rs`.

## Outcome contract

Measure the actual client await for all production TiDB pool checkouts, new-session configuration, schema/open, transaction begin/commit/rollback, and SQL calls in `storage.rs`, `compact.rs`, and `inode_batch.rs`. The pool metric is checkout elapsed, including possible connection creation and `after_connect`, **not** isolated queue wait. SQL elapsed includes client scheduling/network/server response; it cannot identify TiKV or physical I/O. Returned row counts are populated only for typed selected `Option`/`Vec` results; `affected_rows` is not a returned-row count. Payload bytes count only submitted block INSERT bodies and returned block-body SELECT values on successful SQL calls. Static enum labels only; no URL, key, SQL text, raw error, token or path in labels/logs. Durations are inclusive and overlapping, so sums are not exclusive CPU or server time.

## Provider implementation order

1. Core API dependency: import `mount_rs_core::diagnostics::storage::{Operation, Span}` only after the core owner publishes the reserved variants. No new crate dependency.
2. Route all 34 production `pool.get_conn()` awaits through a small typed helper which wraps the *same* driver future and returns the original `MysqlError`. Keep each call's existing `db_error` context at its callsite. Use the same helper for private connect, shared context `OnceCell` initialization/open, flush and compact operations. Count session hook entry/success/error/cancel on both private and shared pools without changing `with_reset_connection(false)` or verification.
3. Record schema DDL and metadata-row open separately from workload SQL. Keep `OnceCell` waiting and fresh session creation visible as distinct scopes; do not subtract nested inclusive durations to infer queue wait.
4. Span the three transaction starts at their actual `start_transaction` await. The shared `commit` helper records acknowledged `Ok`, error, and dropped/cancelled span outcomes, preserving its existing `FsError` and no replay. A commit error or cancellation leaves the transaction outcome unknown. Wrap all five explicit rollback awaits, including `rollback_and`, without changing the original-error return behavior. An abandoned mysql_async guard is not an acknowledged rollback; transaction lifetime and implicit cleanup remain unavailable. Driver-internal work in `start_transaction` and `commit` is included in those elapsed times.
5. Instrument every production `query_*`/`exec_*` await in the manifest with a fixed compile-time class. For `exec_iter`, include `drop_result().await` in the statement completion path. Its `affected_rows()` is not a returned-row count; leave returned rows unavailable until a separate affected-row field exists. For `exec_first` and `exec`, set returned rows from `Option` and `Vec`; for `exec_drop`/`query_drop`, mark row count unavailable. Do not change query methods solely to expose row counts. Known block bytes are the submitted `bytes.len()` on INSERT or returned body length on SELECT, not wire or persisted bytes. Namespace payload bytes remain unavailable in this slice.
6. Re-run the static manifest and source review to account for all production sites, including `compact.rs` and `inode_batch.rs`. Publish fixed `TidbDiagnosticCoverage` site counts and an ordered list of only source-wired operation labels. Its `source_sites_instrumented` status does not assert runtime execution or a live TiDB verification. Existing core and SDK spans nest with these provider spans and cannot be summed as exclusive CPU.
