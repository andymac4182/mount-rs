# Full production target runner implementation plan

> **For agentic workers:** Use subagent-driven-development with one implementation/source/Cargo/native owner and independent specification and quality review. This continues Task 4 of the approved 2026-09-25 remote production qualification design; the user has already approved and authorized its implementation.

**Goal:** Make the real production workload executable through ten independently supervised server processes, preserving the complete requested target and retaining trustworthy failure evidence.

**Architecture:** Add a distinct controller/worker entrypoint and dedicated script. Reuse narrowly extracted shared fixture, token and byte-oracle helpers from the existing production controls. Each child uses the existing public service dispatcher, authenticated TLS QUIC and SDK storage context. The controller performs online population and varied operations, maintains acknowledged expected state and verifies it through fresh stores. Existing bounded checkpoints remain separate.

**Tech Stack:** Rust, Tokio, Quinn, rustls, SDK split storage, SQLite diagnostic controls, preserved actual TiDB fixture, Node/Python/shell only where existing runner/resource contracts require them.
