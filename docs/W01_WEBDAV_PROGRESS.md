This tracker owns WebDAV protocol/XML/locks/authentication, session and
streaming APIs, connection faults, lifecycle, and provider/native boundaries.

Supported-scope PUT atomicity decision: WebDAV intentionally matches the
pinned oracle's in-place write contract. The destination opens at the first
non-empty body chunk, so a request-body failure returns an error while keeping
the bytes already written; WebDAV does not claim atomic PUT publication or
turn `FsDriver::atomic_rename` into a stronger replace guarantee. This is an
explicit protocol-scope decision, not power-loss or provider durability
acceptance.

Durability-barrier decision: when a driver advertises
`Capabilities::durable_writes`, successful WebDAV filesystem mutations await
`FsDriver::syncfs()` before their response is acknowledged. Barrier failures
become request failures; volatile drivers retain the no-op default. Durable
lock persistence is explicitly outside the supported WebDAV scope: the
session lock table is process-local, and the NodeFs/SQLite forced-process-loss
probes verify that a replacement session reports zero locks after reopening.
The structural N-API `FsDriver` seam now forwards an optional `syncfs()`
callback; advertising durable writes without that callback still fails closed
as `ENOSYS`.

## Current queue

  green; its string and public-symbol prototype audit matches the pinned oracle,

  1/2/3 method matrix now pass.
  The N-API boundary for
  `now`, `onAssertion`, and the live `DavLockTable` is explicitly outside the
  supported surface: the Rust transport retains deterministic clock injection,
  while N-API exposes serializable options and read-only lock snapshots.
- Keep Basic authentication strict at the HTTP grammar boundary: the scheme
  must be followed by one or more spaces before the canonical base64 payload;
  the live regression rejects the previously accepted `Basic<base64>` form.
- Keep the listener lifecycle state honest after an accept-loop failure: a
  finished listener task is not a running server, so the next serialized
  `listen()` can bind again instead of returning a false success. The focused
  regression covers both finished and pending Tokio listener-task handles.
- Preserve repeated request fields at every WebDAV boundary: duplicate `If`
  lines are combined with grammar-safe whitespace, while other repeated fields
  are retained for strict downstream parsing rather than silently overwritten.
- Keep absolute-URI authority matching aligned with the pinned oracle for
  `Destination` and tagged `If` resources: compare the URL host and explicit
  port literally, including bracketed IPv6, and do not infer an omitted default
  port before accepting a request.
- Keep public lock-timeout options non-panicking: finite `Timeout` requests
  cap before applying the protocol's one-second minimum, including when a
  caller configures `max_timeout_seconds: 0`; the deterministic regression
  keeps this malformed-option boundary from escaping `handle_request`.
- Keep public lock snapshots deterministic: `DavLockTable::all()` and the
  session's read-only lock records preserve grant order, remove expired or
  deleted tokens from that order, and retain the pinned oracle's duplicate
